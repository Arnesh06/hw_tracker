# HW-Track

Hardware inventory management for labs, departments and teams. Register every board, sensor and instrument once, give it a permanent ID and QR label, and follow who owns it, who holds it and where it went.

Built with **Next.js 15 (App Router) + TypeScript**, **Tailwind CSS + shadcn/ui**, **Supabase** (PostgreSQL, Auth, Storage) and **Recharts**. It runs entirely on the free tiers of **Vercel** and **Supabase**.

## Features

| Area | What you get |
| --- | --- |
| **Components** | Required: name, category, quantity, given by/source, current owner, status, received date. Everything else (manufacturer, model, part/serial number, vendor, purchase date, cost, invoice, warranty, holder, location, project, description, specifications, notes) is optional. |
| **Permanent IDs** | `HW-000001`, `HW-000002`, … generated by a database sequence. They can never be changed or reused. |
| **Dashboard** | Totals for all, available, in use, damaged, in repair and retired; inventory value; status donut; units received per month; top categories; value by project; units by location; recent movements. |
| **Search** | Global search bar (press `/` or `Ctrl K`) across ID, name, owner, holder, source, vendor, project, category, serial/part number, invoice number and notes. |
| **Filters and sorting** | Status, category, project, source, vendor, location, warranty (ending soon / expired) and archived state. Sort by ID, name, category, quantity, status, owner, received date, value or last update. |
| **Assign and transfer** | Assign to a person, transfer ownership, return to stock, move location, change status. Each creates a permanent history entry with an optional note. |
| **History** | A complete, append-only ownership and movement timeline for every component. |
| **Archive** | Components are never deleted. Archiving hides them from totals and makes them read-only; restoring brings them back. |
| **Files** | Images, invoices, datasheets and documents (up to 10 MB each) stored privately in Supabase Storage and served through short-lived signed links. |
| **QR codes** | A QR label per component that opens `/c/HW-000123`. Download PNG/SVG, print label sheets (small/medium/large), and scan with a phone camera, from a photo, or by typing the ID. |
| **Import / export** | CSV and Excel import with a check-first preview, flexible header matching, date parsing (YYYY-MM-DD, DD/MM/YYYY, Excel dates) and optional auto-creation of missing categories, sources, vendors, locations and projects. Export filtered or selected rows as CSV or Excel. |
| **Reference data** | Projects, Providers (given by / source), Vendors, Locations and Categories, with usage counts, deactivate and safe delete. |
| **Reports** | Group by category, project, location, source, vendor, owner, holder or status; condition and value charts; totals; CSV/Excel export; print-friendly. |
| **Audit log** | Every insert, update and delete with before/after values, plus sign-ins, imports, exports and admin actions. Filterable and exportable. Cannot be edited or deleted, even through the API. |
| **Administration** | One Super Admin creates, edits, disables and enables users, resets passwords, edits what each role can do, and grants or denies individual permissions per user. |
| **Notifications** | Bell menu for warranties ending soon or recently expired, and items in repair or damaged. |
| **UI** | Responsive (desktop, tablet, phone), light and dark themes, keyboard shortcuts, loading skeletons, toasts, empty states and print styles. |

## How security works

Permissions are enforced in three independent layers, so hiding a button is never the only protection:

1. **Interface.** Menu items and buttons a user can't use are hidden (`useCan()`).
2. **Server.** Every server action and API route calls `authorize("permission")` before doing anything and returns an error if the user lacks it (`src/lib/auth.ts`).
3. **Database.** Row Level Security policies call `has_permission()` on every read and write (`supabase/migrations/0002_rls.sql`). Even someone calling the Supabase REST API directly with the public key only gets what their role allows.

More guarantees:

- **One Super Admin.** A unique partial index makes a second Super Admin impossible, and the role can't be assigned from the app.
- **No hard deletes.** There is no DELETE policy on components, and the privilege is revoked.
- **Immutable history.** `audit_logs` and `component_movements` are written only by database triggers. Triggers block UPDATE, DELETE and TRUNCATE, and write privileges are revoked.
- **Actors can't be faked.** The acting user and email come from the verified JWT inside the database.
- **Disabled users are cut off everywhere.** Their profile is inactive, so every permission check fails, and they are banned at the Supabase Auth level, which stops token refresh.
- **Accounts are disabled by default.** Accounts created outside the Administration page start disabled, even if public sign-up is accidentally left on.
- **The service-role key stays on the server.** It is used only for Supabase Auth admin calls (create user, ban, reset password), after the caller is verified as Super Admin, and never reaches the browser.
- **Files are private.** The bucket is private; downloads use 60-second signed URLs; uploads must go under `components/<id>/`.
- **Exports are safe to open.** CSV/Excel cells are neutralised against formula injection.
- **Security headers are set:** `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, and a `Permissions-Policy` that allows the camera only for this site (needed for QR scanning).

## 1. Set up Supabase

1. **Create a project.** Go to [supabase.com](https://supabase.com), create a free account and click **New project**.
   - Pick a region close to your users (for India, **Mumbai (ap-south-1)**).
   - Save the database password somewhere safe.
2. **Create the database.** Open **SQL Editor → New query**, paste the whole of `supabase/setup_all.sql` and click **Run**. It should finish with "Success. No rows returned".
   - Alternatively, run `0001_schema.sql`, `0002_rls.sql`, `0003_storage.sql` and then `seed.sql` (optional), in that order.
   - Run it only once, on a fresh project.
3. **Lock down sign-ups.** Go to **Authentication → Sign In / Providers**.
   - **Turn off "Allow new users to sign up".** Users are created only by the Super Admin.
   - Keep **Email** enabled.
   - Accounts created any other way start disabled anyway, but switching sign-ups off keeps the user list clean.
4. **Copy the keys.** Go to **Project Settings → API** (or **API Keys**) and copy:
   - the **Project URL**, which becomes `NEXT_PUBLIC_SUPABASE_URL`;
   - the **anon / publishable** key, which becomes `NEXT_PUBLIC_SUPABASE_ANON_KEY`;
   - the **service_role / secret** key, which becomes `SUPABASE_SERVICE_ROLE_KEY`. Keep this one private.
5. **Check storage.** Under **Storage** you should now see a private bucket called **hw-files**.

## 2. Run locally

Requires **Node.js 20.9+** (22 LTS recommended).

```bash
git clone https://github.com/<you>/hw-track.git
cd hw-track
npm install
cp .env.example .env.local        # then fill in the three Supabase values
```

`.env.local`:

```env
NEXT_PUBLIC_SUPABASE_URL=https://abcdefgh.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...
NEXT_PUBLIC_APP_URL=http://localhost:3000
NEXT_PUBLIC_STORAGE_BUCKET=hw-files
```

**Create the Super Admin** (once):

```bash
node --env-file=.env.local scripts/create-super-admin.mjs you@college.edu 'A-Strong-Passw0rd' "Your Name"
# same thing: npm run create-super-admin -- you@college.edu 'A-Strong-Passw0rd' "Your Name"
```

Start the app:

```bash
npm run dev
```

Open http://localhost:3000, sign in, then go to **Administration → Add user** to invite everyone else.

Useful scripts: `npm run typecheck`, `npm run lint`, `npm run build`.

> Camera scanning needs HTTPS. It works on `localhost` and on Vercel. To test on a phone during development, deploy a preview or use a tunnel (e.g. `cloudflared tunnel --url http://localhost:3000`).

## 3. Deploy to Vercel

1. **Push to GitHub.**
   ```bash
   git init && git add . && git commit -m "HW-Track"
   git branch -M main
   git remote add origin https://github.com/<you>/hw-track.git
   git push -u origin main
   ```
   `.env.local` is git-ignored. Never commit keys.
2. **Import the repo.** At [vercel.com/new](https://vercel.com/new), import the repository. The framework is detected as **Next.js**; leave the build settings at their defaults.
3. **Add environment variables.** Under **Settings → Environment Variables**, add these for Production, Preview and Development:

   | Name | Value |
   | --- | --- |
   | `NEXT_PUBLIC_SUPABASE_URL` | your Project URL |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon / publishable key |
   | `SUPABASE_SERVICE_ROLE_KEY` | service_role / secret key |
   | `NEXT_PUBLIC_APP_URL` | `https://<your-project>.vercel.app` (or your custom domain) |
   | `NEXT_PUBLIC_STORAGE_BUCKET` | `hw-files` |

4. **Deploy.** Click **Deploy**. `NEXT_PUBLIC_*` values are baked in at build time, so if you change them later, **redeploy**.
5. **Point Supabase at the site.** In Supabase, go to **Authentication → URL Configuration** and set **Site URL** to your Vercel URL.
6. **Sign in.** Open the site and sign in with the Super Admin you created.

**`NEXT_PUBLIC_APP_URL` matters.** QR labels encode `NEXT_PUBLIC_APP_URL/c/HW-000123`. Set it to your final production domain before printing labels. If it is unset, the app falls back to Vercel's production URL.

Nothing is written to Vercel's filesystem. All data lives in Supabase Postgres and all files in Supabase Storage, so serverless redeploys are safe.

## Using the app

- **Add a component.** Go to **Inventory → Add component**. Only the essentials are required. The **+** buttons next to dropdowns create a new category, source, vendor, location or project on the spot.
- **Assign, return or transfer.** Use the buttons on the component page. Assigning defaults the status to *In use*; returning defaults it to *Available* and clears the holder.
- **Label hardware.**
  1. Tick rows in the inventory list and choose **Print labels**.
  2. Pick a size and print on sticker paper with margins set to *None*.
- **Scan.** Tap the scan icon in the top bar (or go to **Inventory → Scan**). You can use the camera, a photo, or type the number.
- **Bulk import.**
  1. Go to **Inventory → Import** and download the template.
  2. Fill it in, upload it and click **Check file**.
  3. Review the problems, then import the valid rows.
- **Find anything.** Press `/` anywhere. Typing just a number (e.g. `123`) jumps straight to `HW-000123`.
- **Retire safely.** Archive instead of deleting. Archived items stay searchable (filter: *Active and archived*) and keep their history.

## Database reference

| Object | Purpose |
| --- | --- |
| `profiles` | One row per user: role, active flag. |
| `permissions`, `role_permissions`, `user_permissions` | Permission catalogue, role defaults, per-user grant/deny. |
| `components` | Inventory records; `hw_id` from `hw_id_seq`. |
| `component_movements` | Append-only ownership/location/status history. |
| `component_files` | File metadata; binaries are in Storage. |
| `categories`, `projects`, `providers`, `vendors`, `locations` | Reference data (case-insensitive unique names). |
| `app_settings` | Single row: organization name, currency, warranty alert days. |
| `audit_logs` | Immutable audit trail. |
| `v_components` | View joining names, `total_value` and a `search_text` column (runs with the caller's permissions). |
| `has_permission(key)` | Effective permission check used by RLS. |
| `move_component(...)` | Assign / transfer / return / relocate / status change. |
| `set_component_archived(...)` | Archive or restore. |
| `dashboard_stats()`, `report_grouped(...)`, `master_usage(...)` | Reporting. |
| `admin_update_user`, `admin_set_user_permission`, `admin_set_role_permission` | Super Admin operations. |
| `log_app_event(...)` | Whitelisted application events (sign-in, export, import, admin). |

**Backups.** The free tier doesn't include automatic backups. Export periodically from **Inventory → Export → Excel** and **Audit log → Export CSV**, or run `pg_dump` with the connection string from **Project Settings → Database**.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| "Missing environment variable …" | Add the variable in `.env.local` / Vercel and restart or redeploy. |
| Sign-in works but every page says "You don't have access" | The profile is disabled or the role lacks `inventory.view`. The Super Admin can check under **Administration**. |
| "Could not read profiles. Did you run the SQL migrations?" | Run `supabase/setup_all.sql` first. |
| "A Super Admin already exists" | Only one is allowed. Sign in with that account, or change the role in the Supabase table editor before re-running the script. |
| Camera doesn't start | Use HTTPS, allow camera permission, or use **From a photo**. |
| Uploads fail with "new row violates row-level security" | The user lacks **Upload files**, or the bucket name in `NEXT_PUBLIC_STORAGE_BUCKET` doesn't match. |
| QR codes point to localhost | Set `NEXT_PUBLIC_APP_URL` to the production URL and redeploy. |
| Deleting a project/vendor fails | It is referenced by (possibly archived) components. Deactivate it instead. |
